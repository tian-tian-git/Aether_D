# 02 语义与求值模型(v0.1)

> 状态:候选冻结稿(待 M1 门禁确认)。冻结后任何变更须走 ADR。

## 1. 求值模型

1. **一切皆表达式**:模块、函数、`let`、`if`、`block` 均有值。
2. **严格求值(call-by-value)**:调用实参从左到右逐个求值后再进入函数。
3. **惰性位置**:仅 `(if c then else)`——只对选中分支求值;`block` 顺序求值返回末表达式值。
4. `and`/`or` 在 v0.1 是**内建函数、严格求值**(不短路);若未来需要短路语义,升级为特殊形式并走 ADR。
5. **确定性承诺**:同一程序同一输入必有同一输出;实现不得依赖哈希随机种子影响可观察行为(`Map` 迭代顺序不做承诺)。

## 2. 值模型

| 类型 | 表示 | 说明 |
| :--- | :--- | :--- |
| `Int` | i64 | 算术按**环绕(wrapping)**语义,明确定义、非 UB;除零 → E5xxx |
| `Float` | f64 | IEEE 754 语义 |
| `Bool` | true/false | — |
| `Str` | 不可变 UTF-8 | 长度按字节还是码点?v0.1 标准库只承诺 `str-len` 返回**码点数**,详见 06-std |
| `Vec[T]` | 不可变序列 | 无原地更新;`push`/`concat` 返回新值(结构共享是实现细节,不承诺) |
| `Map[K,V]` | 不可变映射 | 键必须可比较(`==` 结构相等) |
| `Option[T]` | `some x` / `none` | 显式构造,杜绝隐式 null |
| `Result[T,E]` | `ok x` / `err e` | 显式错误通道 |
| `Struct` | 字段映射 | 构造器 = 结构体名调用;字段访问 = `(. obj "field")`(字段名为字符串,显式无魔法) |
| `Fn` | 闭包 | 捕获词法环境;函数值可传参/返回/入容器 |
| `Unit` | `()` | 仅此一值 |
| `Ast` | 语法树值 | `quote` 的产物;`Ast` 值可被 `eval`(M6 起)读取与执行 |

- **不可变默认**:不存在任何赋值或原地更新操作。
- **结构相等**:`==` 对全部值做深结构比较;`!=` 为其否定。

## 3. 作用域与绑定

1. **词法作用域**:`module` 建立模块作用域;`fn` 体、`block` 建立嵌套作用域。
2. **`let` 绑定**:从声明点起,在该作用域**后续**可见(类似 let*);同一作用域内重复绑定同名 → E3xxx(类型检查期)或 E5xxx(解释期兜底)。
3. **具名函数可见性**:模块级 `fn` 的名字在整个模块作用域内可见(含自身体内 → 支持递归);匿名函数无名字,不能直接递归。
4. **遮蔽**:嵌套作用域允许同名遮蔽;同一作用域不允许。
5. **无全局可变状态**:模块级 `let` 是常量绑定;不存在跨模块隐式共享可变状态。

## 4. 函数与调用

1. 调用 `(f a b)`:求值 `f` 得到函数值 → 实参从左到右求值 → 以词法环境 + 实参绑定进入函数体。
2. 结构体名作调用头 = 构造器:`(Point 1.0 2.0)`。
3. 内建函数(算术/比较/集合/IO)同样以普通调用形式使用,见 06-std.md(M2 冻结)。
4. 模块级 `fn main` 是程序入口:元数 0 或 1(1 个参数时类型必须为 `(Vec Str)`,接收命令行参数);`main` 返回 `Unit` 或 `Int`,`Int` 即进程退出码。

## 5. 契约语义

1. **运行时检查(兜底)**:进入函数前逐个求值 `:pre`;返回前逐个求值 `:post`(其中 `result` 绑定返回值);结构体构造时检查 `:invariant`。
2. **违反即失败**:任何契约求值为 `false` → 结构化诊断 E4xxx,含函数名、契约类型、违反的约束表达式与节点定位。
3. **求值环境**:契约表达式在函数环境内求值,可引用参数、模块常量与内建谓词;`sorted`、`permutation` 等验证谓词由 06-std 提供。
4. **静态验证(M3)**:整数/数组域契约转译为 Z3 断言做编译期验证;运行期检查永远保留为兜底。
5. **信任模型**:契约只承诺、不藏实现;契约本身若求值报错,同样报结构化错误(非静默忽略)。

## 6. 效果与 IO

1. **显式效果标记**:`fn` 返回类型后可选 `!`。v0.1 解析器保留该标记,**检查器不做强制**(M4+ 实施效果检查)。
2. **效果内建**:`(out s)` 向 stdout 写一行并返回 `()`;`(err-out s)` 向 stderr 写一行并返回 `()`。除此之外 v0.1 无 IO 能力(无文件、无网络、无 stdin)。
3. **纯度约定**:不含效果内建调用的函数是纯函数,实现可用其做优化(M5 起);标记 `!` 的函数必须显式化其效果来源。

## 7. 错误模型

1. **零未定义行为**:所有操作要么有定义,要么抛出结构化运行时错误(E5xxx);不存在「未定义行为」这一分类。
2. 运行时错误携带:节点 ID、span、错误码、消息、修复建议(见 05-diagnostics)。
3. 典型 E5xxx:除零、空向量 `head`/`tail`、Map 缺键、类型不匹配(解释期兜底)、越界 `get`。

## 8. quote 与同像性

1. `(quote expr)` 不求值 expr,返回其 **Ast 值**。
2. `Ast` 值打印为规范化的 S 表达式,可被解析器回读(round-trip)。
3. v0.1 仅承诺「读」;`eval`/结构补丁列入 M6(自举)范围。

## 9. 命名约定(非强制,示例与 std 遵守)

- 变量/函数:kebab-case(`get-user-name`);类型/结构体:首字母大写(`Point`);谓词以 `?` 结尾(`empty?`、`sorted?`、`permutation?`、`finite?`)。
