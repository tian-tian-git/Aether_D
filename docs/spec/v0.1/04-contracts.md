# 04 契约语义与验证(v0.1)

> 状态:草案(M3 冻结)。契约语法见 01-syntax.md;类型约束见 03-types.md §2.5。

## 1. 契约语义(运行时,02-semantics §5 的细化)

1. **检查时机**:进入函数前逐个求值 `:pre`;返回前逐个求值 `:post`(`result` 绑定返回值);结构体构造时检查 `:invariant`。
2. **违反即失败**:任何契约求值为 `false` → E4001(:pre)/ E4002(:post)/ E4003(:invariant),诊断含「函数名 + 契约表达式节点 ID + span」。
3. **契约必须为 Bool**:静态类型检查强制(E3007);运行期非 Bool 同样报错。
4. **信任模型**:契约只承诺、不藏实现;契约自身求值报错 → 结构化错误,不静默忽略。
5. 验证谓词(`sorted?`/`permutation?` 等)由 06-std 提供,用户代码与契约共用。

## 2. 静态验证(Z3,v0.1 能力边界)

`aether check` 在类型检查后执行**静态契约验证**(`aether-verify::z3bridge`):

1. **支持域**:`Int` / `Bool` / `(Vec Int)` 值;算术(环绕差异为已知限制)、比较、`and`/`or`/`not`;`get`/`len`/`push`/`head`/`vec`/`range`;`if` 双分支符号执行;`let`。
2. **检查内容**:
   - 函数体中的 `get`/`head`:**越界可证实**(SAT 反例)→ E5004,含反例模型;
   - 用户函数调用点:**`:pre` 可被违反**(在调用上下文下 SAT)→ E4001,含反例模型;
   - 函数体完成后:**`:post` 可被违反** → E4002,含反例模型。
3. **不支持则回退**:`Float`/`Str`/`Map`/`Option`/`Result`/结构体/`sorted?`/`permutation?` 等无法静态翻译的表达式——子树静默跳过,由运行期检查兜底;**静态验证不产生误报**(只报可证实的违反,unknown 按「未证实」处理)。
4. **已知限制(如实声明)**:
   - `Int` 按 Z3 无界整数(与 Aether i64 环绕语义在溢出时不一致);
   - 除法按 Z3 欧几里得语义(负数除法与运行期截断不一致);
   - 递归函数体不展开(调用点契约检查仍生效);
   - 每次 `aether check` 新建 Z3 上下文,无跨调用状态。
5. **后端依赖**:libz3.dll(z3-solver 5.x 即可);查找顺序:环境变量 `AETHER_Z3_PATH` → pip 用户安装路径 → 系统 PATH。不可用 → 检查降级为「跳过静态验证」并提示(E6001),运行期检查不受影响。

## 3. 分层验证总览

| 层 | 时机 | 覆盖 | 产物 |
| :--- | :--- | :--- | :--- |
| 静态类型 | `check`/`run` 前置 | 全部表达式 | E3xxx |
| 静态契约(Z3) | `check` | 上述支持域 | E4001/E4002/E5004 + 反例模型 |
| 运行期契约 | 每次调用/构造 | 全部契约 | E4001–E4003 + 节点定位 |
