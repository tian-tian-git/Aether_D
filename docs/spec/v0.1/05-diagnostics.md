# 05 结构化诊断规范(v0.1)

> 状态:候选冻结稿(待 M1 门禁确认)。
> 诊断是 M4「AI 生成回路」的地基:每一条诊断都必须可被程序消费、可被 LLM 直接利用。

## 1. 总原则

1. **结构化优先**:诊断一律以机器可读结构(JSON)产出,人类可读文本由 CLI 渲染层生成。
2. **可定位**:每条诊断必须携带 `span`;来自 AST 的诊断必须携带 `node_id`。
3. **可行动**:必须携带 `code`(稳定错误码)与 `hints[]`(修复建议,至少一条)。
4. **语言**:`message` 与 `hints` 用英文书写(对 LLM 语料友好、可检索);错误码是程序消费的第一键。

## 2. JSON Schema(草案)

```json
{
  "diagnostics": [
    {
      "node_id": 42,
      "severity": "error",
      "code": "E2001",
      "message": "expected ')' to close the list opened at 1:12",
      "span": { "start": {"offset": 120, "line": 6, "col": 1},
                "end":   {"offset": 121, "line": 6, "col": 2} },
      "hints": ["insert a closing ')' here"]
    }
  ]
}
```

- `node_id`:全局唯一整数(AST 节点编号);词法错误没有节点,字段缺省。
- `severity`:`error` | `warning` | `hint`(v0.1 只产出 `error`)。
- `span`:`offset` 为字节偏移,`line`/`col` 为 1 起算的人类可读位置;`col` 按码点计数。
- `hints[]`:面向「下一轮生成」的修复建议,可多条。

## 3. 错误码注册表

| 区间 | 阶段 | 说明 |
| :--- | :--- | :--- |
| E1xxx | 词法 | 已注册:E1001 孤立分号、E1002 未闭合字符串、E1003 非法字符、E1004 整数字面量溢出、E1005 非法转义序列、E1006 非法数字字面量(均无 node_id) |
| E2xxx | 解析 | 已注册:E2001 意外 token/输入过早结束、E2002 未闭合括号、E2003 多余的 `)`、E2004 形式元数错误、E2005 形式位置非法(嵌套 module、struct/let 出现在表达式位置)、E2006 期望标识符、E2007 期望类型、E2008 契约种类与形式不匹配 |
| E3xxx | 类型检查(M3) | 类型不匹配、重复绑定 |
| E4xxx | 契约(M3) | pre/post/invariant 违反,含契约定位 |
| E5xxx | 运行时 | 除零、空容器访问、缺键等 |
| E6xxx | 验证后端(M3+) | Z3 交互、SMT 翻译失败 |

具体错误码在实现各阶段注册(每个错误码一条单测锁定消息与结构)。

## 4. 对 AI 生成回路的约定(M4 消费)

1. harness 以 `code` + `node_id` + `hints` 组装下一轮修补提示,**不**把原始堆栈喂给 LLM。
2. 同一条诊断信息在程序文本不变时保持稳定(可缓存、可回归)。
3. 诊断输出的 JSON 是公共接口:改动字段必须走 ADR 并更新本文件。

## 5. 渲染

- CLI 人类可读渲染:`error[E2001]: expected ')' ...` + 源码片段 + 波浪线指示 + hints。
- `--json` 开关输出 2 节 Schema(供 harness 与测试断言使用)。
