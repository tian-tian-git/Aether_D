## M1 语法与解析 🟡(进行中)

**目标**:冻结语言规范 v0.1 并实现完整的前端(词法 → 解析 → AST → 打印)。

**工作包**(WP1.1 先行;WP1.2–1.6 在其后并行,文件边界不重叠):

| 编号 | 工作包 | 涉及文件 | 依赖 |
| :--- | :--- | :--- | :--- |
| WP1.1 | 冻结 spec v0.1(语法/语义/类型/契约/诊断章节) | `docs/spec/v0.1/*` | — |
| WP1.2 | AST 完整节点 + Span/NodeId | `crates/aether-ast/*` | WP1.1 |
| WP1.3 | 词法分析器 + 递归下降解析器 | `crates/aether-parser/src/lexer.rs`、`parser.rs` | WP1.2 |
| WP1.4 | 打印器 + round-trip 属性测试 | `crates/aether-parser/src/printer.rs`、`tests/` | WP1.2 |
| WP1.5 | 结构化诊断模型(错误码 + 位置 + 建议 + JSON 序列化) | `crates/aether-diagnostic/*` | — |
| WP1.6 | 示例集与 CLI `parse` 子命令 | `examples/`、`crates/aether-cli/*` | WP1.3 |

**退出标准**:
1. `examples/` 全部程序通过解析,`aether parse <file>` 输出 AST dump;
2. round-trip 属性测试通过(parse → print → parse 相等);
3. 所有诊断含 NodeId/位置/错误码/修复建议,并有单测覆盖;
4. spec v0.1 冻结(人类总监在门禁确认)。

**检查点**:人类总监审阅 spec v0.1 冻结稿。

## 协作与执行模型

- **每轮节奏**:主智能体更新状态板 → 并行派发子智能体(文件边界不重叠)→ 收集结果 → 合并提交 → 向人类总监汇报。
- **并行上限**:同一里程碑内最多 3 个子智能体并行;核心语义决策(类型系统、后端选型)由主智能体定,细节执行放权。
- **门禁清单**(人类总监确认点):M0 框架审阅 / M1 spec 冻结 / M5 后端选型 / 其余里程碑按退出标准走门禁报告。
